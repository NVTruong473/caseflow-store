# v1.16.0 - Cross-device Experience And Password Assurance

Release date: 2026-07-28

Production: `https://caseflow-store.vercel.app`

Vercel deployment: `dpl_9Nmny2kZdcvM2NgHNMcP4vdgjG5X`

## Summary

`v1.16.0` turns the isolated checkout walkthrough into an expiring
cross-device experience and adds role-aware password assurance. It also ships
contextual customer guidance and the sign-in/header UX fixes accumulated after
`v1.15.0`.

The release does not add real payment collection. Completing the QR experience
cannot create or pay an order, change inventory, redeem a voucher, send a
commerce notification, or count as revenue.

## Cross-device QR Experience

- Added an RLS-protected `checkout_experience_sessions` table and atomic
  completion RPC through migration `0014`.
- Server recalculates totals from active catalog records; the phone never
  supplies the authoritative amount.
- QR URLs use an HTTPS fragment capability so raw tokens do not enter initial
  request logs or referrers.
- The phone must match the exact server amount and a separate six-digit code
  shown on the authenticated desktop.
- Raw tokens/codes are not persisted. Sessions expire by server time, lock
  after five failed attempts, and complete idempotently.
- Desktop polling stops at terminal states and updates without a page reload.
- The no-index phone page contains no customer name, email, address, cart lines,
  account password, bank credential, or real-bank deep link.

## Password Assurance

- Customers request a single-use Supabase recovery link sent only to the
  signed-in account email.
- `/account/password-reset` establishes only a recovery session, removes bearer
  tokens from the visible URL, updates the password, signs out, and returns to
  the account page.
- The normal customer password endpoint fails closed.
- Admin/staff changes require the current password plus
  `OPERATIONS_PASSWORD_CHANGE_SECRET`, compared on the server in constant time.
- Both new secrets are configured as sensitive Vercel variables and are absent
  from tracked source and client bundles.

## Customer UX

- Direct customer sign-in returns to the storefront while safe explicit return
  paths such as checkout remain supported.
- Desktop and mobile navigation show the authenticated customer's profile name.
- Bilingual, accessible first-use tours cover storefront buying, cart actions,
  checkout modes, and order-history cancellation with explicit replay.
- Guidance state stores only completed tour IDs and no customer or commerce
  content.
- Transfer-experience brand text now uses the centralized storefront
  configuration for buyer customization.

## Known Boundaries

- No real payment, bank account, wallet, settlement, refund, or logistics
  provider is connected.
- Supabase's default Auth sender delivered the authorized recovery-email test,
  but custom SMTP, sender-domain authentication, abuse controls, and monitoring
  remain buyer prerequisites.
- The shared admin/staff operations secret is a showroom control, not
  enterprise MFA.
- Full dependency audit retains the documented dev-tooling advisory chain.
