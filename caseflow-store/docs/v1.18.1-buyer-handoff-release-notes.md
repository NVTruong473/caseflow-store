# CaseFlow Books v1.18.1

## Clean-room Buyer Handoff Patch

`v1.18.1` addresses two setup blockers found by extracting the published
source package into an isolated directory and following only its `README.md`.
It does not add storefront features, change database schema, or enable any
external provider.

## Deployment Reliability

- Keeps static sitemap routes available when the catalog database is
  temporarily unreachable during a Production build.
- Omits product URLs only for that failed catalog read instead of failing the
  complete deployment.
- Continues to include live product URLs when Supabase is available.

## Environment Contract

- Treats whitespace-only optional FX values as absent and falls back to the
  validated default source URL, quote timestamp, exchange rate, VAT, and
  international-fee values.
- Prevents an unchanged `.env.example` from causing a runtime configuration
  error.
- Keeps required Supabase and server-secret values mandatory.

## Public Source Package

- Exports package version `1.18.1`, matching the release tag and archive.
- States explicitly that runtime storefront and commerce checks require a
  buyer-owned, reachable Supabase project with schema, migrations, and seed
  applied.
- Adds the runtime-only dependency audit command and rejects unsafe forced
  major dependency changes used only to hide development-tool warnings.
- Preserves the 832-file allowlist, one-Markdown rule, proprietary license,
  500-edition customer-data-free seed, and no-secret boundary.

## Explicit Boundaries

- A fresh buyer-owned Supabase project was not created because no isolated
  account/project credentials were supplied and creating external resources
  can have ownership or billing consequences.
- The package does not provide a mock database fallback. Full customer,
  operator, checkout, and order acceptance requires the buyer to apply the
  supplied SQL to their own Supabase project.
- Nine high-severity npm audit findings remain in the development-only
  ESLint/minimatch dependency path. Runtime dependencies have zero findings.
  The available ESLint 10 upgrade was tested and rejected because it breaks the
  current Next.js ESLint plugin API.
