# v1.15.0 - Isolated Checkout QR Experience

Release date: 2026-07-27

## Summary

`v1.15.0` separates real order placement from a safe QR walkthrough on the
CaseFlow Books checkout. Visitors can inspect and complete the QR interaction
without creating a fake sale, while the existing account-gated order flow
continues to use server-owned prices, vouchers, inventory, and order history.

## Checkout

- Added accessible `Place order` and `QR experience` tabs in English and
  Vietnamese.
- Kept official checkout as the default and preserved its profile, shipping,
  voucher, payment-method, idempotency, inventory, and order behavior.
- Added keyboard navigation for the checkout tabs.
- Added QR loading, pending, countdown, completed, expired, error, and reset
  states with desktop and mobile layouts.

## Transaction Boundary

- The QR experience uses the latest cart returned by `/api/cart/validate`.
- It creates an internal `caseflow-experience://` payload and local-only state.
- It calls no order, payment, or mock simulate-success endpoint.
- It cannot alter inventory, vouchers, notifications, order history, sales, or
  admin analytics.
- It uses the visibly non-real account number `0000000000` and cannot open a
  bank or wallet application.
- Existing persisted mock/VietQR providers and simulate-success controls remain
  locked in Production.

## Display Fix

- Rebuilt the checkout-success summary as a responsive detail grid.
- Localized order status instead of exposing raw enum values.
- Contained long order codes, payment methods, payment statuses, and totals at
  desktop and 375px mobile widths.

## Boundaries

- This is a portfolio-safe experience, not payment settlement.
- No real bank account, wallet, webhook, refund, reconciliation, or payment
  provider was introduced.
- Real payment enablement still requires a contracted provider, merchant
  identity, secrets, signed webhooks, reconciliation, refund handling, and a
  separate security and operations review.
