# CaseFlow Books v1.18.2

## QR Experience History And Retry Recovery Patch

`v1.18.2` fixes two customer-facing gaps in the cross-device QR experience
without converting practice activity into a real order or payment.

## Customer Experience

- Adds a separate `QR experience history` section to the signed-in customer's
  order-history page.
- Shows recent customer-owned practice references, amounts, statuses, and
  timestamps without mixing them into official orders.
- Adds a direct action from a completed experience back to official checkout.
- Keeps the cart intact after practice so the customer can place the intended
  order through the official flow.
- Synchronizes the QR phone page language with the complete page shell when a
  language is carried in the scan URL.

## Confirmation Recovery

- Keeps an experience session pending after an incorrect six-digit
  confirmation until the existing five-attempt limit is reached.
- Clears the incorrect code, returns focus to the code field, updates the
  remaining-attempt count, and permits a corrected submission.
- Retains server-side amount validation, hashed confirmation matching,
  idempotent completion, expiry, and lock behavior.

## Commerce And Security Boundary

- Experience completion still creates no order or payment.
- It does not change stock, vouchers, notifications, sales analytics, or admin
  order metrics.
- It does not clear cart or Buy Now state.
- The history repository filters by the authenticated customer ID and selects
  only the safe read model. Capability tokens, confirmation codes and hashes,
  salts, cart fingerprints, and customer PII are not exposed.
- Production mock-payment simulation remains unavailable.

## Schema

No migration is required. The history uses the existing
`checkout_experience_sessions` table accepted by ADR-0021.

## Explicit Boundary

An experience history entry proves only that the internal practice values
matched. It is not proof of funds, a commercial transaction, an order, or a
fulfillment obligation. Only the official checkout creates a customer order.
